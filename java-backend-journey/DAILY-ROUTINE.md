# Daily Study Routine — Java Backend Developer Journey

**Target:** 2 hours 30 minutes per study day (150 minutes).  
**Rule:** The topic listed for a day in `ROADMAP.md` is only the main learning topic, not the whole day's study.

## 1. Complete this routine every study day

- [ ] **Java / Backend concept — 30 min:** Study the topic assigned for today in `ROADMAP.md`.
- [ ] **Independent coding — 60 min:** Write the day's programs from a blank editor. Test edge cases; do not copy a solution.
- [ ] **DSA — 30 min:** Solve or make meaningful progress on one problem. Record the approach and complexity.
- [ ] **Project / revision — 30 min:** Follow the phase guide below.
- [ ] **Progress record:** Update `DAILY-TRACKER.md`, create a dated log in `daily-logs/`, and commit your work.

If you have only one hour available, record what you completed; do not mark the full day complete.

## 2. DSA rotation — repeat every week

| Day | DSA focus |
|---|---|
| Monday | Arrays |
| Tuesday | Strings |
| Wednesday | HashMap / HashSet |
| Thursday | Two pointers |
| Friday | Binary search |
| Saturday | Recursion / sorting |
| Sunday | Revision: redo problems without looking at solutions |

Start with easy problems. Focus on explaining the approach and writing the code yourself before increasing difficulty.

## 3. Project / revision block — what to do in those 30 minutes

| Weeks | Project / revision focus |
|---|---|
| 1–4 | Revisit Java programs; add validation and test cases. Build small console exercises such as a calculator and BankAccount. |
| 5–8 | Practise SQL and JDBC; connect Java code to a practice database when ready. |
| 9–12 | Build the Banking Transaction Monitoring System incrementally: setup, entities, repositories, services, controllers and REST APIs. |
| 13–16 | Add authentication, authorization, validation, unit tests and integration tests. |
| 17–20 | Add microservices concepts, Kafka, Redis, resilience and distributed-systems patterns. |
| 21–24 | Dockerize the project; practise Kubernetes, CI/CD, debugging, system design and interview explanations. |

## 4. When to study system design and microservices

Do not force advanced system design and microservices into every day from Week 1. Build the foundations first.

- **Weeks 1–8:** Prioritise Core Java, OOP, collections, Java 8, SQL, JDBC and DSA.
- **Weeks 9–12:** Learn Spring Boot, REST APIs, JPA/Hibernate and basic application architecture.
- **Weeks 13–16:** Learn Spring Security, testing and maintainable backend structure.
- **Weeks 17–20:** Study microservices and distributed systems. Add two focused system-design sessions per week, using some project/revision time.
- **Weeks 21–24:** Practise system design and production architecture regularly alongside Docker, Kubernetes and interview preparation.

## 6. How to use the GitHub files

- `ROADMAP.md`: main topic assigned to each day.
- `DAILY-TRACKER.md`: tick a day after completing its full study routine.
- `DAILY-ROUTINE.md`: keep this routine open every study day.
- `templates/DAILY-LOG.md`: copy it to create a dated daily log.
- `WEEKLY-TRACKER.md`: update your weekly milestone every Sunday.

**Completion standard:** Reading or watching a topic is not enough. You should be able to explain it and write a working solution independently.
